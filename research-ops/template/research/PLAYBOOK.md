# PLAYBOOK：失败模式 → 诊断 → 对策
/triage 用 Grep 匹配「症状」列。诊断按成本从低到高排列；对策写清主选和备选。项目特有的条目追加在文末。

## 决策原则
1. 先排除 bug（数据、预处理、评估口径），再调超参，最后才改方法。
2. 每个对策先估 GPU·h，便宜的先做；能用 10 分钟冒烟验证的就不要直接跑全量。
3. 差异小于 seed 间标准差的不算结论；关键对比至少 3 个 seed。
4. 同一方向连续 2 次 ❌：停下复盘，必要时找外部评审（/review-packet）。
5. 负结果也有价值：记进 DECISIONS，并考虑改写成消融或局限性。

## A. 工程
| 症状 | 诊断（先便宜的） | 对策 |
|---|---|---|
| OOM | gpuq 已自动按 ×1.3 重试；看 digest 的峰值；batch 与分辨率 | 主：梯度检查点 + bf16 + 更小的 micro-batch 加梯度累积。备：只在需要时解码或计算 loss，减少保留的中间量 |
| loss 出现 NaN/Inf | 第一次出现的 step；lr warmup；bf16/fp16 溢出；除零（如面积为 0）；数据里有 NaN | 主：在出错 step 附近 `torch.autograd.detect_anomaly`，给分母加 eps、clamp。备：降 lr、加梯度裁剪、对出问题的 loss 改用 fp32 计算 |
| GPU 利用率低（< 60%） | nvidia-smi 的 util；dataloader 等待时间；CPU 是否打满 | 主：离线预计算（如 VAE latent）并放进内存；增加 num_workers；pin_memory。备：减少同卡并发数（`--cpus` 给大一点） |
| 同卡多任务互相拖慢 | 单任务吞吐 vs 并发吞吐 | 小模型并发收益大，大模型并发几乎不增加吞吐：调 `max_jobs_per_gpu`，或对大任务用 `-x` |
| 任务卡住、日志没有更新 | digest 的 modified 时间；py-spy dump；NCCL 超时 | 主：设 NCCL_TIMEOUT 与 watchdog。备：取消后从最近的 checkpoint 恢复 |
| 结果不可复现 | seed、cudnn.deterministic、数据顺序、git dirty | 主：rlog 记录 commit 与 config；关键实验固定 seed 并跑 3 个 |
| 磁盘满 | `df -h`；checkpoint 数量 | 只保留 best/last，旧 checkpoint 定期清理（清理前先问我） |

## B. 训练动态
| 症状 | 诊断 | 对策 |
|---|---|---|
| loss 不下降 | 能否过拟合 1 个 batch；lr 范围扫描；标签与输入是否对齐 | 主：先让单 batch 过拟合，确认实现无误。备：调 lr（×0.3 / ×3）、检查归一化 |
| 过拟合（train↑ val↓） | train/val 曲线分叉的 step | 主：早停 + 增广。备：减小模型或加正则 |
| val 指标震荡 | val 集大小；EMA；评估口径 | 主：用 EMA 权重评估、扩大 val。备：降 lr 或加 cosine 衰减 |
| 比公开 baseline 差很多 | 复现官方配置；评估脚本是否对齐（分辨率、帧选取、后处理） | 主：先 1:1 复现官方数字，再改。备：逐项对齐差异 |

## C. 生成模型
| 症状 | 诊断 | 对策 |
|---|---|---|
| 条件不遵循（生成结果的属性和条件不一致） | 用独立评估器测条件遵循度；CFG 权重扫描；条件丢弃率 | 主：扫 CFG 权重。备：增加条件丢弃训练步数或辅助 loss |
| 样本模糊或有伪影 | 解码器重建上限；采样步数；EMA | 主：先测 VAE 重建上限，确认瓶颈在哪里。备：增加采样步数，换 Heun |
| 多样性低 / 模式崩塌 | precision 高但 recall 低；最近邻检索 | 主：降 CFG、加噪声多样性。备：检查是否过拟合训练集（记忆化检测） |
| FID/FVD 与人眼观感不一致 | 特征提取器与领域是否匹配；样本数 N | 主：同时报告领域特征（领域编码器）下的指标；N ≥ 2048 |
| 少步采样质量崩塌 | teacher 在少步时的曲线；直线度指标 | 主：蒸馏或 reflow 前先测 teacher 在 2/4/8 步的表现，作为 go/no-go 依据 |
| 蒸馏 / reflow 后学生劣化 | 配对数量；配对质量；生成数据与真实数据的分布偏移 | 主：增加配对或加入真实数据配对。备：降低目标 NFE（2→4） |

## D. 评估与统计
| 症状 | 诊断 | 对策 |
|---|---|---|
| 提升小于 seed 方差 | 3 seed 的 mean ± std；配对检验 | 加 seed，或承认无显著差异并改写结论 |
| VAL 好、TEST 差 | 是否在 TEST 上调过参；划分是否泄漏 | 只在 VAL 选模型；TEST 只评一次 |
| 与 baseline 口径不一致 | 分辨率、帧、后处理、指标实现 | 用同一份评估脚本重跑 baseline |
| 数据泄漏嫌疑 | 预训练权重见过哪些划分；患者是否在多个划分中重复出现 | 设「严格轨道」（只用 TRAIN 从零训练）作为主表口径 |

## E. 论文层面
| 症状 | 诊断 | 对策 |
|---|---|---|
| 主假设被否定 | 是否只在某个设置下不成立 | 收窄主张（只在成立的设置上声称）；或把它转为分析型贡献 |
| 增益只来自额外数据，而不是方法 | 有没有「同样数据、不用方法」的对照 | 补充公平对照（同样的无标签数据 / 伪标签） |
| 审稿人可能问「为什么不直接用 X」 | 有没有对应的对照实验 | 在实验矩阵里加对照，或在讨论中正面回答 |
